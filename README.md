# Booking Service — сайт-візитка з резервацією часу + адмінка через Telegram

Універсальний веб-сервіс бронювання часу. Клієнти бачать красиву мобільну
вітрину з картками (майстри/консультанти/об'єкти) і резервують вільний час
через календар. **Уся адмін-панель — це Telegram-бот**: додавання карток,
завантаження фото/відео, керування графіком.

## Структура проєкту

```
booking-service/
├── server.js              # точка входу: Express + запуск бота
├── package.json
├── .env.example            # шаблон змінних середовища
├── db/
│   ├── database.js         # підключення SQLite + схема таблиць
│   └── queries.js          # весь доступ до даних (items, media, schedule)
├── routes/
│   └── api.js               # REST API для фронтенду
├── bot/
│   ├── index.js             # ініціалізація бота, авторизація, меню
│   ├── keyboards.js         # inline-клавіатури
│   └── scenes/
│       ├── addItemScene.js      # покроковий wizard додавання картки
│       ├── editItemScene.js     # редагування картки
│       ├── deleteItemScene.js   # видалення картки
│       ├── mediaScene.js        # завантаження фото/відео
│       └── scheduleScene.js     # блокування часу / вихідні дні
└── public/
    ├── index.html           # весь фронтенд (Tailwind + Swiper + Flatpickr)
    └── uploads/              # сюди бот зберігає фото/відео (автоматично)
```

База даних SQLite (`booking.db`) створюється автоматично при першому
запуску сервера — окремо нічого налаштовувати не потрібно.

### Структура БД

- **items** — назва/опис/послуги (окремо CZ і EN), номер WhatsApp,
  тривалість бронювання за замовчуванням.
- **media** — фото/відео, прив'язані до `item_id`.
- **schedule** — записи графіку: `booked` (заброньовано), `pending`
  (заявка з сайту, очікує підтвердження адміном), `day_off` (вихідний день).

## 1. Встановлення

Знадобиться **Node.js 18+** (для вбудованого `fetch`, який використовує бот
для завантаження медіа з Telegram).

```bash
cd booking-service
npm install
```

Це встановить пакети:
- `express` — веб-сервер і API
- `better-sqlite3` — синхронна робота з SQLite
- `telegraf` — Telegram Bot API
- `dotenv` — змінні середовища
- `nodemon` (dev-залежність, для розробки з автоперезапуском)

## 2. Створення Telegram-бота

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримайте
   **BOT_TOKEN**.
2. Дізнайтеся свій **ADMIN_CHAT_ID**, написавши
   [@userinfobot](https://t.me/userinfobot) — він покаже ваш числовий ID.
   Тільки цей ID матиме доступ до адмін-меню бота.

## 3. Налаштування середовища

```bash
cp .env.example .env
```

Відкрийте `.env` і впишіть свої значення:

```
PORT=3000
BOT_TOKEN=ваш_токен_від_BotFather
ADMIN_CHAT_ID=ваш_числовий_id
BASE_URL=http://localhost:3000
```

## 4. Запуск

```bash
npm start          # звичайний запуск
# або
npm run dev         # з автоперезапуском при змінах (nodemon)
```

Після запуску:
- Сайт доступний на `http://localhost:3000`
- Напишіть своєму боту `/start` у Telegram — відкриється адмін-меню

## 5. Як користуватись адмінкою (Telegram)

Надішліть боту `/start` або `/menu`:

- **📋 Список карток** — переглянути всі картки та їх статус
- **➕ Додати картку** — покроковий майстер: назва CZ/EN, опис CZ/EN,
  послуги CZ/EN (через кому), номер WhatsApp, тривалість бронювання (хв)
- **✏️ Редагувати картку** — оберіть картку → оберіть поле → введіть нове
  значення
- **🗑 Видалити картку** — видаляє картку разом з її медіа й графіком
- **🖼 Керувати медіа** — оберіть картку, потім просто надсилайте боту фото
  чи відео одне за одним; натисніть «✅ Готово», коли завершите
- **📅 Керувати графіком**:
  - «⛔ Заблокувати конкретний час» — вкажіть дату, час і тривалість
  - «🚫 Позначити вихідний день» — вкажіть дату, весь день стане недоступним
  - «📋 Переглянути / видалити записи» — список і видалення записів

Коли клієнт із сайту надсилає заявку на бронювання, бот одразу присилає вам
повідомлення з кнопками **✅ Підтвердити** / **❌ Відхилити**. Час
блокується на сайті одразу після подання заявки (статус `pending`), навіть
до вашого підтвердження — це запобігає подвійному бронюванню. Якщо
відхилити заявку, час одразу звільняється.

## 6. Розгортання на сервері (production)

Найпростіший варіант — VPS (Ubuntu) з `pm2`:

```bash
npm install -g pm2
cd booking-service
npm install --production
pm2 start server.js --name booking-service
pm2 save
pm2 startup   # налаштує автозапуск при перезавантаженні сервера
```

Рекомендується поставити перед сервісом Nginx як реверс-проксі з
HTTPS-сертифікатом (Let's Encrypt/Certbot), проксіюючи на `localhost:3000`.

## 7. Як розширювати проєкт далі

Архітектура навмисно розділена на шари, щоб додавати нове було просто:

- **Нове поле картки** → додайте колонку в `db/database.js`, дозвольте її
  редагування в `items.updateField` (`db/queries.js`), додайте крок у
  `addItemScene.js`/`editItemScene.js`, виведіть на фронтенді.
- **Новий крок в адмінці** → додайте нову сцену в `bot/scenes/` і
  зареєструйте її в `bot/index.js` (`stage` + пункт меню).
- **Новий ендпоінт для сайту** → додайте роут у `routes/api.js`, він одразу
  матиме доступ до `bot` (для сповіщень) і до `db/queries.js`.
- **Мультивалютні онлайн-оплати, e-mail-сповіщення, статистика** — усе це
  природно лягає в `routes/api.js` та `db/queries.js`, не чіпаючи фронтенд
  чи бота.

## Примітки з безпеки

- Middleware в `bot/index.js` жорстко звіряє `ctx.from.id` з
  `ADMIN_CHAT_ID` — будь-хто інший отримає відмову й жодних дій виконати
  не зможе.
- Ніколи не публікуйте `.env` і не комітьте `booking.db` у git (обидва вже
  в `.gitignore`).
